Desarrollo de Módulos

Crear un módulo nuevo requiere seguir la arquitectura estricta del framework. Tal y como dicta el script check_module_integrity.sh, existen 5 archivos obligatorios y varios opcionales para funciones avanzadas.

¡Importante! Nombres Estrictos: No puedes nombrar estos archivos como quieras. El núcleo del orquestador (AssemblyScript.sh, daemon.sh) está programado para buscar y ejecutar exactamente estos nombres de archivo. Si los renombras, el framework simplemente los ignorará.

Archivos Obligatorios

Deben existir en src/modules/tu_modulo/.

1. module.sh

El script de Bash que ejecuta la lógica y exporta una variable HTML. Se ejecuta de forma segura y aislada mediante un subshell.

Ejemplo:
#!/bin/bash
export MI_MODULO_HTML=""
# Lógica...
if [ 1 -eq 1 ]; then
    MI_MODULO_HTML="<p>Todo correcto en el servidor.</p>"
fi

2. template.html

La plantilla visual de la caja que contendrá los datos. Invoca las variables exportadas.

Ejemplo:
<div class="module-container">
    <h3 class="module-title">${L_TITLE_MI_MODULO}</h3>
    ${MI_MODULO_HTML}
</div>

3. locales/ (Carpeta de Traducciones)

Debe contener al menos en.sh (además de es.sh y fr.sh) con las variables lingüísticas.

Ejemplo:
# Archivo locales/es.sh
L_TITLE_MI_MODULO="⚙️ Mi Módulo"
L_TEXT_SUCCESS="Todo correcto"

4. README.md & LICENSE

Archivos estándar de texto explicando la finalidad técnica del módulo y su licencia legal de código abierto.

Archivos Opcionales (Funciones Avanzadas)

Los siguientes scripts solo son necesarios si tu módulo utiliza la base de datos MariaDB para guardar métricas históricas, o requiere binarios de Linux externos.

5. packages.txt

Si tu módulo necesita binarios nativos del sistema operativo, lístalos aquí. El orquestador los instalará dinámicamente con apt-get al hacer build.

Ejemplo:
net-tools
iproute2

6. schema.sql

Si tu módulo necesita guardar histórico de datos, este archivo se ejecutará al iniciar el contenedor para crear la tabla de forma segura. Importante: Debes escribir la sentencia explícita IF NOT EXISTS en tu código SQL para evitar conflictos o errores de sintaxis cuando el contenedor se reinicie o se vuelva a crear.

Ejemplo:
CREATE TABLE IF NOT EXISTS mod_mimodulo_datos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    dato INT NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

7. collect.sh

Script de Bash que se ejecutará en segundo plano (orquestado por daemon.sh cada pocos minutos) para recabar métricas continuas e insertarlas en la base de datos.

Ejemplo:
#!/bin/bash
DATO_ACTUAL=$(free -m | awk '/^Mem:/{print $3}')
mysql -h 127.0.0.1 -P 33060 -u root -p${DB_ROOT_PASSWORD} healthcheck -e "INSERT INTO mod_mimodulo_datos (dato) VALUES ($DATO_ACTUAL);"

8. prune.sh

Script de Bash ejecutado justo después de enviar el informe para purgar datos viejos de tu tabla, evitando que el disco se llene infinitamente.

Ejemplo:
#!/bin/bash
mysql -h 127.0.0.1 -P 33060 -u root -p${DB_ROOT_PASSWORD} healthcheck -e "DELETE FROM mod_mimodulo_datos WHERE timestamp < NOW() - INTERVAL 7 DAY;"

9. cleanup.sql

Script SQL ejecutado automáticamente por sync_modules.sh si el administrador desactiva el módulo en el archivo de configuración. Debe borrar tus tablas por completo para no dejar basura o "datos huérfanos".

Ejemplo:
DROP TABLE IF EXISTS mod_mimodulo_datos;
