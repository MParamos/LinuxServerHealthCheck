Casos de Uso y Requisitos

Antes de desplegar LinuxServerHealthCheck (LSHC), es importante entender para qué escenarios está diseñado y qué necesita tu infraestructura para ejecutarlo de manera óptima.

🎯 ¿Para quién es esta herramienta?

  • Administradores de Sistemas y DevOps: Ideal para auditar flotas de servidores sin ensuciar el sistema operativo (host) con agentes pesados.
  • PYMES y Startups: Una alternativa gratuita, privada y Zero-Maintenance frente a costosas soluciones SaaS de monitorización corporativa.
  • Comunidad Homelab y Entusiastas: Perfecto para vigilar servidores personales (NAS, Proxmox, Raspberry Pi) recibiendo informes limpios directamente al correo.

⚙️ Requisitos Técnicos

El framework es extremadamente ligero por su compilación dinámica, pero requiere los siguientes componentes base en la máquina anfitriona:

  • Sistema Operativo: Prácticamente cualquier distribución Linux moderna basada en systemd (Ubuntu, Debian, CentOS, RHEL, Arch Linux, Fedora).
  • Motor de Contenedores: Docker Engine y Docker Compose (V2+).
  • Permisos Estrictos: El contenedor debe ejecutarse imperativamente en modo privileged: true y montar la raíz del sistema (/:/host:ro). Esto es necesario para que los comandos internos (ej. chroot /host systemctl o smartctl) puedan auditar el hardware y los servicios del host de manera Air-Gapped.
  • Red: Acceso de salida al puerto SMTP de tu proveedor de correo (generalmente 587 o 465) para poder emitir los informes. No requiere puertos de entrada abiertos.
