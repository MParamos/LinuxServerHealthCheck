Requisitos de los Módulos

Para mantener la imagen Docker lo más ligera posible, el sistema utiliza Resolución Dinámica de Dependencias.

Si un módulo necesita un comando específico (como nmap, smartmontools o lm-sensors), simplemente incluye un archivo llamado packages.txt en su raíz, listando los paquetes APT línea por línea.

Durante el docker compose build, el Dockerfile leerá ModulesInReport.conf, iterará sobre los módulos activos, concatenará sus archivos packages.txt, e instalará exactamente y únicamente lo necesario.

Estructura Mínima Obligatoria

Para garantizar la estabilidad del framework, el orquestador verifica la integridad estructural de cada módulo antes de ejecutarlo. Esta validación se realiza en cada ejecución mediante el script interno check_module_integrity.sh.

Si un módulo no posee los archivos estrictamente necesarios, el orquestador lo aislará y mostrará una alerta roja en el informe en lugar de colapsar.

Los archivos obligatorios que todo módulo debe tener son:

  • module.sh: El script ejecutable en Bash que contiene la lógica del módulo.
  • template.html: El diseño HTML de la caja del módulo, con variables (ej. $MI_VARIABLE).
  • README.md: Documentación técnica básica sobre lo que hace el módulo.
  • LICENSE: El archivo de licencia (generalmente MIT o GPL).
  • locales/: La carpeta obligatoria que debe contener, como mínimo, un archivo en.sh (además de es.sh y fr.sh si están soportados) con las traducciones.

Archivos Opcionales (Funciones Avanzadas)

Si el módulo requiere interactuar con la base de datos o instalar utilidades del sistema, puede incluir de manera opcional:

  • packages.txt: Dependencias a instalar mediante apt-get.
  • schema.sql: Estructura de tablas SQL (ejecutado al arranque).
  • collect.sh: Script para recolección de métricas en segundo plano.
  • prune.sh: Script para limpieza recurrente de registros antiguos.
  • cleanup.sql: Script SQL de borrado total, ejecutado al desactivar el módulo.

Nota: Tienes un desglose completo con ejemplos de código de todos los archivos en la sección Desarrollo de Módulos.

Ejemplo de Estructura de Módulo

src/modules/mi_nuevo_modulo/
├── LICENSE
├── README.md
├── module.sh
├── template.html
└── locales/
    ├── en.sh
    ├── es.sh
    └── fr.sh
