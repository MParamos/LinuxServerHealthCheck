Module Dependencies

To keep the Docker image as lightweight as possible, the system uses Dynamic Dependency Resolution.

If a module needs a specific command (like nmap, smartmontools or lm-sensors), simply include a file named packages.txt in its root, listing the APT packages line by line.

During the docker compose build, the Dockerfile will read ModulesInReport.conf, iterate over active modules, concatenate their packages.txt files, and install exactly and only what is needed.

Mandatory Minimum Structure

To guarantee framework stability, the orchestrator verifies the structural integrity of each module before executing it. This validation is performed on every run by the internal check_module_integrity.sh script.

If a module lacks the strictly required files, the orchestrator will isolate it and display a red alert box in the report instead of crashing.

The mandatory files that every module must possess are:

  • module.sh: The executable Bash script containing the module's logic.
  • template.html: The HTML layout for the module's box, using variables (e.g. $MY_VARIABLE).
  • README.md: Basic technical documentation explaining what the module does.
  • LICENSE: The license file (usually MIT or GPL).
  • locales/: The mandatory folder that must contain, at a minimum, an en.sh file (alongside es.sh and fr.sh if supported) for translations.

Optional Files (Advanced Features)

If the module requires interacting with the database or installing system utilities, it may optionally include:

  • packages.txt: Dependencies to install via apt-get.
  • schema.sql: SQL tables structure (executed at startup).
  • collect.sh: Script for background metric collection.
  • prune.sh: Script for recurrent cleanup of old records.
  • cleanup.sql: Total wipe SQL script, executed when deactivating the module.

Note: You can find a complete breakdown with code examples of all files in the Module Development section.

Example Module Structure

src/modules/my_new_module/
├── LICENSE
├── README.md
├── module.sh
├── template.html
└── locales/
    ├── en.sh
    ├── es.sh
    └── fr.sh
