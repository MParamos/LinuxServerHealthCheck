Module Development

Creating a new module requires following the framework's strict architecture. As dictated by the check_module_integrity.sh script, there are 5 mandatory files and several optional ones for advanced features.

Important! Strict Naming: You cannot name these files whatever you want. The orchestrator core (AssemblyScript.sh, daemon.sh) is hardcoded to find and execute exactly these filenames. If renamed, the framework will ignore them.

Mandatory Files

They must exist in src/modules/your_module/.

1. module.sh

The Bash script that executes logic and exports an HTML variable. It runs safely and isolated within a subshell.

Example:
#!/bin/bash
export MY_MODULE_HTML=""
# Logic...
if [ 1 -eq 1 ]; then
    MY_MODULE_HTML="<p>Server is running fine.</p>"
fi

2. template.html

The visual template for the data box. It calls the exported variables.

Example:
<div class="module-container">
    <h3 class="module-title">${L_TITLE_MY_MODULE}</h3>
    ${MY_MODULE_HTML}
</div>

3. locales/ (Translation Folder)

Must contain at least en.sh (along with es.sh and fr.sh) with linguistic variables.

Example:
# File locales/en.sh
L_TITLE_MY_MODULE="⚙️ My Module"
L_TEXT_SUCCESS="Everything is fine"

4. README.md & LICENSE

Standard text files explaining the technical purpose of the module and its open-source legal license.

Optional Files (Advanced Features)

The following scripts are only necessary if your module uses the MariaDB database to store historical metrics, or requires external Linux binaries.

5. packages.txt

If your module needs native OS binaries, list them here. The orchestrator will dynamically install them with apt-get during the build.

Example:
net-tools
iproute2

6. schema.sql

If your module needs to save historical data, this file will run at container startup to create the table safely. Important: You must explicitly write the IF NOT EXISTS statement in your SQL code to prevent conflicts or syntax errors when the container restarts or is recreated.

Example:
CREATE TABLE IF NOT EXISTS mod_mymodule_data (
    id INT AUTO_INCREMENT PRIMARY KEY,
    data INT NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

7. collect.sh

Bash script executed in the background (orchestrated by daemon.sh every few minutes) to gather continuous metrics and insert them into the database.

Example:
#!/bin/bash
CURRENT_DATA=$(free -m | awk '/^Mem:/{print $3}')
mysql -h 127.0.0.1 -P 33060 -u root -p${DB_ROOT_PASSWORD} healthcheck -e "INSERT INTO mod_mymodule_data (data) VALUES ($CURRENT_DATA);"

8. prune.sh

Bash script executed right after sending the report to purge old data from your table, preventing infinite disk growth.

Example:
#!/bin/bash
mysql -h 127.0.0.1 -P 33060 -u root -p${DB_ROOT_PASSWORD} healthcheck -e "DELETE FROM mod_mymodule_data WHERE timestamp < NOW() - INTERVAL 7 DAY;"

9. cleanup.sql

SQL script executed automatically by sync_modules.sh if the administrator deactivates the module in the configuration file. It must completely drop your tables to avoid leaving orphaned data.

Example:
DROP TABLE IF EXISTS mod_mymodule_data;
