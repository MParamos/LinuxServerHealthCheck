Use Cases & Requirements

Before deploying LinuxServerHealthCheck (LSHC), it is important to understand which scenarios it is designed for and what your infrastructure needs to run it optimally.

🎯 Who is this tool for?

  • Sysadmins and DevOps: Ideal for auditing server fleets without polluting the host operating system with heavy monitoring agents.
  • SMEs and Startups: A free, private, and Zero-Maintenance alternative to expensive corporate SaaS monitoring solutions.
  • Homelab Community and Enthusiasts: Perfect for monitoring personal servers (NAS, Proxmox, Raspberry Pi) receiving clean reports directly via email.

⚙️ Technical Requirements

The framework is extremely lightweight due to its dynamic compilation, but requires the following base components on the host machine:

  • Operating System: Practically any modern Linux distribution based on systemd (Ubuntu, Debian, CentOS, RHEL, Arch Linux, Fedora).
  • Container Engine: Docker Engine and Docker Compose (V2+).
  • Strict Permissions: The container must imperatively run in privileged: true mode and mount the system root (/:/host:ro). This is required so internal commands (e.g. chroot /host systemctl or smartctl) can audit the host's hardware and services in an Air-Gapped manner.
  • Network: Outbound access to your email provider's SMTP port (usually 587 or 465) to dispatch the reports. No open inbound ports are required.
