Dépendances des Modules

Afin de garder l'image Docker aussi légère que possible, le système utilise la Résolution Dynamique des Dépendances.

Si un module nécessite une commande spécifique (comme nmap, smartmontools ou lm-sensors), incluez simplement un fichier nommé packages.txt à sa racine, listant les paquets APT ligne par ligne.

Lors du docker compose build, le Dockerfile lira ModulesInReport.conf, itérera sur les modules actifs, concaténera leurs fichiers packages.txt, et installera exactement et uniquement ce qui est nécessaire.

Structure Minimale Obligatoire

Pour garantir la stabilité du framework, l'orchestrateur vérifie l'intégrité structurelle de chaque module avant de l'exécuter. Cette validation est effectuée à chaque exécution par le script interne check_module_integrity.sh.

Si un module ne possède pas les fichiers strictement requis, l'orchestrateur l'isolera et affichera une boîte d'alerte rouge dans le rapport au lieu de planter.

Les fichiers obligatoires que tout module doit posséder sont :

  • module.sh : Le script Bash exécutable contenant la logique du module.
  • template.html : La mise en page HTML pour la boîte du module, utilisant des variables (ex: $MA_VARIABLE).
  • README.md : Documentation technique de base expliquant ce que fait le module.
  • LICENSE : Le fichier de licence (généralement MIT ou GPL).
  • locales/ : Le dossier obligatoire qui doit contenir, au minimum, un fichier en.sh (en plus de es.sh et fr.sh si pris en charge) pour les traductions.

Fichiers Optionnels (Fonctionnalités Avancées)

Si le module doit interagir avec la base de données ou installer des utilitaires système, il peut inclure de manière facultative :

  • packages.txt : Dépendances à installer via apt-get.
  • schema.sql : Structure des tables SQL (exécuté au démarrage).
  • collect.sh : Script pour la collecte de métriques en arrière-plan.
  • prune.sh : Script pour le nettoyage récurrent des anciens enregistrements.
  • cleanup.sql : Script SQL de suppression totale, exécuté lors de la désactivation du module.

Note : Vous pouvez trouver une description complète avec des exemples de code de tous les fichiers dans la section Développement de Modules.

Exemple de Structure de Module

src/modules/mon_nouveau_module/
├── LICENSE
├── README.md
├── module.sh
├── template.html
└── locales/
    ├── en.sh
    ├── es.sh
    └── fr.sh
