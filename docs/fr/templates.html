Modification des Templates

La vue finale du rapport envoyé est générée en joignant un modèle de base (master) et plusieurs modèles de modules (partials). Les deux systèmes de modèles utilisent du HTML standard injecté avec des variables via le script orchestrateur Bash.

Structure des Modèles

1. Modèle Principal (Master)

Situé dans src/templates/report.html. C'est le "squelette" de l'e-mail et il inclut les en-têtes HTML, les styles CSS et le conteneur global. Il définit une macro-variable ${MODULES_HTML}, où tout le contenu généré par chaque module sera injecté.

2. Modèles de Modules (Partials)

Situés dans src/modules/nom_du_module/template.html. Ce sont des "blocs" qui représentent les informations d'un module particulier. Ils sont toujours structurés sous une <div class="module-container"> pour assurer l'uniformité dans le rapport final.

Comment Ils s'unissent

Lorsque l'orchestrateur s'exécute :

  1. Il lit le template.html de chaque module actif.
  2. Il remplace ses variables internes (ex. ${L_TITLE} ou ${METRIC_VALUE}) par des données réelles.
  3. Il concatène tous ces blocs générés dans une grande variable en mémoire.
  4. Il ouvre src/templates/report.html, cherche ${MODULES_HTML} et y injecte toute la concaténation précédente, produisant le HTML final.

La seule chose qui doit être obligatoirement respectée, conformément à la section 7(b) de la licence GPLv3 (préservation des mentions légales et de la paternité), est qu'il n'est pas permis de supprimer ma paternité ni le lien vers la licence originale du pied de page (footer) du modèle principal (report.html). Vous pouvez déplacer le pied de page si vous le souhaitez, mais il doit rester visible pour le destinataire de l'e-mail.
