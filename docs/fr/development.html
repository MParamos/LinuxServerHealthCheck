Développement de Modules

La création d'un nouveau module nécessite de suivre l'architecture stricte du framework. Comme dicté par le script check_module_integrity.sh, il y a 5 fichiers obligatoires et plusieurs fichiers optionnels pour des fonctionnalités avancées.

Important ! Nommage Strict : Vous ne pouvez pas nommer ces fichiers comme bon vous semble. Le cœur de l'orchestrateur (AssemblyScript.sh, daemon.sh) est programmé pour rechercher et exécuter exactement ces noms de fichiers. S'ils sont renommés, le framework les ignorera.

Fichiers Obligatoires

Ils doivent exister dans src/modules/ton_module/.

1. module.sh

Le script Bash qui exécute la logique et exporte une variable HTML. Il s'exécute de manière sûre et isolée dans un subshell.

Exemple :
#!/bin/bash
export MON_MODULE_HTML=""
# Logique...
if [ 1 -eq 1 ]; then
    MON_MODULE_HTML="<p>Le serveur fonctionne bien.</p>"
fi

2. template.html

Le modèle visuel de la boîte de données. Il appelle les variables exportées.

Exemple :
<div class="module-container">
    <h3 class="module-title">${L_TITLE_MON_MODULE}</h3>
    ${MON_MODULE_HTML}
</div>

3. locales/ (Dossier de Traduction)

Doit contenir au moins en.sh (ainsi que es.sh et fr.sh) avec les variables linguistiques.

Exemple :
# Fichier locales/fr.sh
L_TITLE_MON_MODULE="⚙️ Mon Module"
L_TEXT_SUCCESS="Tout va bien"

4. README.md & LICENSE

Fichiers texte standard expliquant l'objectif technique du module et sa licence légale open-source.

Fichiers Optionnels (Fonctionnalités Avancées)

Les scripts suivants ne sont nécessaires que si votre module utilise la base de données MariaDB pour stocker des métriques historiques, ou s'il requiert des binaires Linux externes.

5. packages.txt

Si votre module a besoin de binaires natifs du système d'exploitation, listez-les ici. L'orchestrateur les installera dynamiquement avec apt-get lors de la phase de build.

Exemple :
net-tools
iproute2

6. schema.sql

Si votre module a besoin de sauvegarder des données historiques, ce fichier s'exécutera au démarrage du conteneur pour créer la table de manière sécurisée. Important : Vous devez explicitement écrire l'instruction IF NOT EXISTS dans votre code SQL afin d'éviter les conflits ou les erreurs de syntaxe lors du redémarrage ou de la recréation du conteneur.

Exemple :
CREATE TABLE IF NOT EXISTS mod_monmodule_data (
    id INT AUTO_INCREMENT PRIMARY KEY,
    data INT NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

7. collect.sh

Script Bash exécuté en arrière-plan (orchestré par daemon.sh toutes les quelques minutes) pour recueillir des métriques continues et les insérer dans la base de données.

Exemple :
#!/bin/bash
DONNEES_ACTUELLES=$(free -m | awk '/^Mem:/{print $3}')
mysql -h 127.0.0.1 -P 33060 -u root -p${DB_ROOT_PASSWORD} healthcheck -e "INSERT INTO mod_monmodule_data (data) VALUES ($DONNEES_ACTUELLES);"

8. prune.sh

Script Bash exécuté juste après l'envoi du rapport pour purger les anciennes données de votre table, empêchant la croissance infinie du disque.

Exemple :
#!/bin/bash
mysql -h 127.0.0.1 -P 33060 -u root -p${DB_ROOT_PASSWORD} healthcheck -e "DELETE FROM mod_monmodule_data WHERE timestamp < NOW() - INTERVAL 7 DAY;"

9. cleanup.sql

Script SQL exécuté automatiquement par sync_modules.sh si l'administrateur désactive le module dans le fichier de configuration. Il doit supprimer complètement vos tables pour éviter de laisser des données orphelines.

Exemple :
DROP TABLE IF EXISTS mod_monmodule_data;
